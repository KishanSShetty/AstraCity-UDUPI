1. Executive Summary 
 
AstraCity is a real-time, map-based waste collection routing platform designed for HSR Layout 
(Ward 174), Bengaluru. It operationalises BBMP's official shapefile data — 336 DWCCs, 11 Bio-
Methanisation Units, 8 Waste Processing Units, and 3 dumpyards — into an animated, 
intelligent, multi-vehicle routing system visible on a live map. 
 
The platform serves BBMP operations staff, ward commissioners, and city-level SWM planners 
to optimise 55 tonnes/day of waste generated in HSR Layout, reduce vehicle idle time, cut per-
tonne collection costs, and meet SWM Rules 2016 compliance requirements. 
 
Core Problem 
HSR Layout generates ~55 TPD across 110,000 residents. Today's routing is manual, static, and 
unoptimised — leading to missed pickups, overloaded vehicles, and unnecessary fuel burn. Wet 
waste travels untracked to Kudlu BMU (2.1 km), dry waste sits at DWCCs without load-balancing, 
and all routing decisions are made on paper. 
 
Core Solution 
A live map dashboard with animated vehicle routing, real-time BBMP data integration, AI-
powered route optimisation (OR-Tools VRP), and Google Gemini-powered natural language 
query bar. Built on Next.js 14, MapLibre GL JS, and OSRM routing — deployable as a web app 
accessible on desktop and mobile.

3. Product Vision & Goals 
 
3.1 Vision Statement 
Vision 
"A living map of HSR Layout where every waste vehicle, every collection point, and every routing 
decision is visible, optimised, and accountable — in real time." 
 
3.2 Product Goals 
1. OPERATIONAL: Provide a real-time animated map of all 7+ collection vehicles with live 
GPS-style routing across HSR Layout's 2,027 road segments. 
2. OPTIMISATION: Use OR-Tools Capacitated VRP to minimise total vehicle distance 
while respecting road-width constraints, vehicle capacity, and BBMP time windows (6 
AM–10 AM primary, 10 AM–6 PM secondary). 
3. INFRASTRUCTURE: Surface all BBMP facility data (DWCCs, BMUs, Processing Units, 
Dumpyards) as interactive map layers with routing overlays. 
4. INTELLIGENCE: Integrate Google Gemini 1.5 Flash for natural language queries about 
ward data, risk scores, route efficiency, and cost savings. 
5. COMPLIANCE: Enforce SWM Rules 2016 source segregation mandates, KSPCB liquid 
waste restrictions, and IRC road classification vehicle compatibility. 
6. ECONOMICS: Calculate and surface carbon credit value, cost-per-tonne metrics, and 
ROI projections for waste infrastructure investments.

5.4.2 DWCC Capacity Model 
• 
Each DWCC assigned a daily capacity (default 3 TPD per unit based on BBMP norms) 
• 
Load % calculated from: (dry waste routed to DWCC) / (DWCC daily capacity) × 100 
• 
Alert thresholds: Yellow at 70%, Red at 90%, Critical (overflow) at 100% 
• 
The 6 in-ward DWCCs collectively handle 16.5 TPD dry waste — avg 2.75 TPD each

6.5 Data Flow Architecture 
6.5.1 Vehicle Animation Data Flow 
7. User opens Vehicle Simulation page (/vehicle-sim) 
8. Next.js server component loads GeoJSON files from /data/ at request time 
9. Client component mounts MapLibre GL JS with dark OSM basemap 
10. VehicleStore (Zustand) initialized with 7 vehicle objects: {id, type, lat, lng, route, status} 
11. API call to /api/vrp → OR-Tools VRP solver returns zone assignments 
12. Per-vehicle: /api/route?coords=[...] → OSRM returns road-snapped GeoJSON LineString 
13. RouteLayer renders LineStrings as animated dashed lines on map 
14. VehicleLayer animates vehicle icons along route using requestAnimationFrame 
15. WebSocket (or polling every 5s) updates vehicle positions from simulated GPS 
16. On DWCC overflow: alert fires → ManualOverride UI allows supervisor reassignment 
 
6.5.2 OSRM Route Computation 
• 
Endpoint: https://router.project-osrm.org/route/v1/driving/{lon1,lat1;lon2,lat2;...} 
• 
Parameters: overview=full&geometries=geojson&steps=true&annotations=true 
• 
Response: geometry (GeoJSON LineString), distance (metres), duration (seconds), legs 
array 
• 
All coordinates in WGS 84 (EPSG:4326) — matching BBMP shapefile CRS 
• 
Rate limit: ~1 req/sec on public OSRM; consider self-hosted for production 
 
6.5.3 OR-Tools VRP Formulation 
• 
Input: N stops (DWCC/BMU coordinates), K vehicles, vehicle capacities, road-width 
constraints 
• 
Distance matrix: Haversine distances between all stop pairs (pre-computed) 
• 
Constraints: vehicle capacity (TPD), time windows (6–10 AM / 10–6 PM), road-width 
compatibility 
• 
Objective: Minimize total distance across all vehicle routes 
• 
Output: Assignment of stops to vehicles + ordered sequence per vehicle 
• 
Algorithm: Clarke-Wright Savings heuristic as initial solution → OR-Tools CVRPTW 
solver
